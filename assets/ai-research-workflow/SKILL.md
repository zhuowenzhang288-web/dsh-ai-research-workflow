# 科研工作流

定位：方向无关的科研操作系统。阶段化推进 + 门控把关 + 全程证据纪律。
模块按需调用、默认参数可调；不要求每次跑完全链路。逐步推进，严格区分四类陈述：**论文事实｜我方假设｜已实现机制｜实验结果**——永远不混。

**配套工具**（scripts/ 下，纯 Python 标准库，任何能跑 bash 的 agent 都能用；用 `python3 scripts/<名>.py` 调用）：

| 脚本 | 对应环节 | 用法 |
|---|---|---|
| `novelty_check.py` | §2 查新 | `python3 scripts/novelty_check.py "关键词"` 查 arXiv 出候选 |
| `experiment_log.py` | §4 实验日志 | `add` 记录一次实验 / `list` 汇总 keep·discard·crash |
| `verify_citations.py` | §7.3 引用审计 | 核验报告里的 arXiv/DOI，输出幻觉率 HR |
| `audit_chain.py` | §7.3 审计链 | 逐层过五层审计，汇总 PASS/WARN/FAIL/BLOCKED |

## 0. 触发机制（命中即执行，先于一切）

当判断当前任务属于本 skill 范围（选题/查新/拆论文/争议地图/实验设计/评审/写作/回应中的任一项），
**立即做两件事，不要等、不要只挂在嘴上**：

1. **告知用户**：先用一句话说明正在做什么查找，例如"正在检索该方向的已有工作，稍等"。简短、只说一次。
2. **派子 agent 去查**：把检索/查新任务派给子 agent——默认用 `subagent`（独立上下文、自包含 prompt，
   带齐具体问题/检索范围/输出格式），是否升级为共享记忆按下面的三档规则判断。让它搜真实工作、拉原文、核引用。

- **子 agent 必须向主 agent 汇报**：返回的不是"查完了"这种话，而是一份结构化结果——
  查了什么、命中了哪些工作（带链接/编号/来源）或跑出什么指标、哪些没查到或存疑、一句话结论。
  主 agent 汇总所有汇报后，才把它作为后续步骤的依据；子 agent 的发现不自动等于结论。

- **检查点汇报（近似"实时"）**：工具层的 `subagent` 是运行到结束才返回，没有原生流式汇报。
  所以要"实时"就把长任务**切成多个短轮次**：每完成一个可交付的检查点（找到一批文献、跑完一小批实验、
  核完一组引用）就结束该子 agent 并回报，主 agent 据此决策后再派下一轮。不要派一个跑一小时的长子 agent 然后干等。
  - 每份检查点汇报同样结构化：本轮做了什么｜新增发现（带来源）｜存疑/未决｜建议下一步。
  - 关键发现可让子 agent 落盘为 artifact（写文件），主 agent 读文件而非靠记忆传递。

- **主 agent 收到汇报后必须做的三件事（动态编排）**：

  1. **判断新知识**：这条发现改变了什么？是否推翻/更新已有结论或假设？按证据四分标注后并入 artifact。
  2. **决定是否注入**：这条知识该不该传给其他正在跑或将要跑的子 agent？
     注入 = 由主 agent 把该结论显式写进目标子 agent 的 prompt（即 B 档转述），**不是**让它们共享记忆。
     只注入相关的、确实需要的 agent；评审/审计 agent 永不接收执行者的中间结论（见硬边界）。
  3. **决定是否开新 agent**：现有子 agent 覆盖不了新发现时，才派生新的子 agent（新问题、新方向、
     需要不同角色如评审/核验）；能并入现有子 agent 后续轮次的就不新开。开新 agent 时同样带齐自包含 prompt。

  这三步是主 agent 的核心职责：**它负责编排与知识路由，子 agent 只负责执行与回报**。
  决策留痕（把"何时把哪条知识注入了谁、为何新开 agent"记入日志），便于回溯。

- **记忆共享按耦合度分三档，不一刀切**：

  | 档 | 什么时候用 | 怎么做 |
  |---|---|---|
  | **A 完全隔离**（默认） | 任务彼此独立，不依赖对方任何结果（并行检索几个方向、并行跑不同配置的实验） | `subagent`，自包含 prompt，不带会话上下文、不带其他子 agent 产物，各跑各的各自汇报 |
  | **B 显式转述** | 任务相关，但只需要对方的**结论/产物**，不需要对方的推理过程（串行查新：第二轮据第一轮命中调整检索；下一批实验据上一批归纳的规律） | 仍用 `subagent` 独立上下文，由主 agent 把上一轮汇总结论或 artifact 路径**显式写进**下一轮 prompt |
  | **C 共享上下文** | 任务高度耦合，需要反复引用对方的中间推理/状态、互相纠错 | `subagent_fork` 继承上下文，或干脆同一 agent 内串行完成 |

  判据：问"它需要对方的**推理过程**，还是只要**结论**？"——只要结论用 B，要推理过程才用 C，都不需要就用 A。
  默认 A，升级到 B/C 必须有明确理由。

- **硬边界（不可用"相关"破坏）**：**评审者/审计者永远不与执行者共享记忆**——无论归入哪一档。
  执行/评审分离是 §0 总原则，跨模型评审者只读原始 artifact，不看执行者的摘要或推理。
- 子 agent 返回的事实仍按"证据四分"标注；存疑/未查到的如实保留，不替它脑补。
- 若任务确实不需要任何外部查找（例如直接评审一段已有文本），跳过发送子 agent，
   但仍用一句话说明"此任务不需要外部检索"，避免用户误以为漏做。
- 若检索工具不可用（网络不通/无 API），如实告知用户"检索受限"，并标注哪些结论未经核验。

## 0. 总原则（任何任务都适用）

1. **证据四分**：输出中明确标注一句话是原论文事实、我方推测、已实现机制还是实验结果；推测和影响范围未证实的解释标为"假设"。
2. **单一事实源**：关键产物落盘为纯文本 artifact——选题漏斗、实验日志、叙事报告、claim 清单——后续步骤从这些文件读，不靠会话记忆；每个结论能指回证据位置。
3. **执行/评审分离**：不评审自己的工作。能跨模型评审时用不同模型家族做独立评审，评审者只看原始 artifact（文件路径/原文），不看执行者的摘要或解释；同模型家族的自评只能作为 provisional，不当作通过。
4. **门内自主、门前停人**：门 = ①查新通过 ②扩大实验规模 ③投稿/出终稿。门内循环自主推进、不反复询问；门前必须交出产物等用户确认。
5. **查不到就说查不到**：论文、引用、数据、结果找不到就标注，不编造；摘要只用于初筛，不作通读依据。

## 1. 选题

**idea 的来源（按优先级，绝不凭空想）**：

1. **现象驱动（默认、优先）**：先跑小实验找规律（§4.2.1 造现象）——规律 → 解释 → idea。
   agent 凭空想 idea 的能力弱、查新存活率低（实战：24 方向 0 存活），规律比直觉可靠。
2. **文献驱动（次选）**：从已读论文的 limitation / 未覆盖边界挖 idea（§3 拆论文 + §2 查新）。
3. **凭空想 idea 是最后手段**，且要预期"高概率白做"——先想 idea 再查新，等于先射箭再画靶。

顺序铁律：**能走现象驱动就别走文献驱动；能走文献驱动就别凭空想。** 反过来（凭空想→查新→实验）是本 skill 要戒掉的旧逻辑。

### 1.1 反向追问（提出任何方案之前依次问）

1. 真实应用任务是什么？
2. 现有方法默认了什么条件？
3. 哪个条件在真实场景可能不成立，证据是什么？
4. 方法改变了什么决策，与简单换模块有何区别？
5. 哪些只是猜想，不能当结论？

用户希望独立回答时不代填，回答含糊继续追问；可并行推进不依赖答案的独立工作。产出表：研究问题｜现实约束｜待验假设｜证据路径。

### 1.2 选题漏斗（持久 artifact）

维护一张漏斗表，至少含：来源｜题目｜研究问题｜方法｜与在研项目的重合｜证据｜待查事项｜状态｜下一步。结合日常文献整理，不重复下载、不虚构论文。**失败/被淘汰的想法也入库**（含淘汰原因），作为反重复记忆；同一方向累计 ≥3 次失败时主动提示换切入点。

**失败想法的记忆管理（防止污染主 agent 上下文）**：

- 子 agent 默认独立上下文（§0 的 A/B 档），其内部失败推理不会自动进入主 agent——**唯一入口是它返回的结构化汇报**。
- 主 agent 收到汇报后，对失败/被否决的想法只做两件事：①抽**一行摘要**（想法 + 淘汰原因 + 证据路径）写进漏斗 artifact；②**不把失败推理链展开进自己的上下文**。失败细节留在文件里，不留在对话里。
- 后续子 agent 的 prompt **不带失败想法的完整推理**，只带一条"已否决清单"（每项一句话 + 原因）；确需细节时给文件路径，让它自己去读。
- 上下文压缩/会话交接时，**优先丢弃失败推理过程，保留结论与淘汰原因**。
- 已否决清单是"防重踩"的负面记忆，不是限制创新：只挡"同一条件下的同一错误"，不挡换了条件或反例后的重新尝试。

### 1.3 CCF-A 顶会/顶刊适配性判断（查新后执行）

**前置**：必须先完成 §2 三轮查新，**且按 §2 的取证标准读到正文**（不得只读摘要就判）。没读正文就不知道"相对已有工作贡献在哪"，此时只能答"待查新后判断"，不得给出 A 类结论。

问的不是"方向热不热"，而是三件事：

1. 问题是否是该领域公认的重要/开放问题（而非自设的小问题）？
2. 相对已有工作，能否给出**文献没有的可证伪新预言**（新问题/新机制/新证据/已知现象的深挖翻新），而非增量调参？
3. 放进目标 venue 近 3 年的录用论文里，它处于什么位置（偏强 / 持平 / 明显偏弱）？

#### 六维打分（各 1–5，必须给证据）

| 维度 | 5 分 | 1 分 |
|---|---|---|
| 问题重要性 | 领域公认开放难题，解决后有广泛影响 | 自设小众问题，只有自己关心 |
| 新颖性 | 能给出**文献没有的可证伪新预言**（哪怕是撞车现象的深挖翻新） | 只是复述已知结论，无新预言 |
| 方法深度 | 有原理性洞察或新方法，说得出"为什么 work" | 标准 pipeline 拼接，无机制解释 |
| 证据强度 | 多数据集 + 强基线 + 消融 + 统计检验 | 单数据集、无消融、无可比基线 |
| 叙事潜力 | 有清晰 story，或有反直觉发现 | 结果平淡，无洞察 |
| Venue fit | 与近 3 年该会同类录用论文相当或偏强 | 明显不对口，或低于门槛 |

#### 红旗项（触发加重审查，不直接否决）

查新遇到以下情况时，**不要一票否决**，而要逐项追问"重合到哪一步、差异是否站得住"：

- 核心方法已有先例 → 追问：是**同一问题 + 同一方法 + 同一结论**（真重复），还是只覆盖其中一两项？
  后者不叫重复，叫增量——只要差异能说清、证据够强，就是正常研究。
- 只是换模块 / 换数据集 / 调超参 → 追问：有没有因此暴露新现象、新失败模式、新的适用边界？有则是贡献，无才是凑数。
- 无可核验的定量结果路径 → 先问是"还没做"还是"做不了"：前者是计划，后者才是红旗。
- 只在单数据集 / 单设置验证 → 看领域惯例：探索性工作可接受，但必须标注验证范围、不越界宣称。
- 依赖不可复现环境 / 私有数据 → 追问是否有公开替代或可释放版本。

**唯一真正否决的情况**：查新确认与某工作**实质完全相同**（问题、方法、主要结论高度重合且无新证据/新洞察），
且无法指出任何站得住的差异——此时才淘汰，并记入漏斗。**"有先例"本身不是否决理由。**

#### 输出与判定

表：研究问题｜六维分数｜总分（/30）｜命中的红旗｜差异论证｜判定｜理由｜补强清单（按 §7.1 分档）。

- 总分 ≥ 24 且**新颖性、问题重要性均 ≥ 4** → 强 A 候选，可进实验设计
- 18–23 → 边缘，按补强清单补强后重判
- < 18 → 不够 A（但仍需给出具体短板，不能只写"有先例"）
- 仅当实质重复且差异不成立 → 直接淘汰，记入漏斗

评分时"新颖性"看的是**相对最近工作的差异强度**，不是"有没有人做过相邻方向"。差异清楚、证据扎实的增量工作，新颖性可以给 3–4 分，不该因存在相关工作就被压到 1–2 分。
**尤其**：撞车的现象/方法里深挖出"文献没测过的旋钮维度 + 可证伪新预言"（例：捷径接管的一阶相变撞车 grokking，但"宽度管捷径、深度管核心"是新预言），新颖性照给高分——**撞车不是零分，翻不出新预言才是零分。**

**声明**：这是研究判断，不是录用概率。不同子领域的 A 类清单不同（如 AI 的 NeurIPS/ICML/ICLR、系统/安全/数据库各有自己的 A 类会与刊）；venue fit 必须对照目标 venue 近 3 年论文，不凭印象。目标 venue 由用户指定或确认，不静默默认。

## 2. 查新（第一道门）

- **先用 `scripts/novelty_check.py` 拉候选**：`python3 scripts/novelty_check.py "关键词"` 直接查 arXiv，拿到带编号/年份/摘要的候选清单（摘要级，只用于初筛）。
- **查新取证标准（硬规则，防"只读摘要就判"）**：
  - **摘要只能用于初筛**（判断这篇是否可能相关），**不能用于任何 KEEP/KILL 判定**。
  - 判定"新/旧"必须读正文相关部分，至少覆盖：**方法**（怎么做的、关键设计）、**实验**（数据集、指标、主结果）、**关键图表**（结论对应的图/表）；附录若有消融、局限、失败案例也要看。
  - 查新报告必须逐篇标注**读取程度**：摘要级 / 正文节 / 全文。只标"摘要级"的篇目**不得出现在 KEEP/KILL 结论里**。
  - 只读摘要就写下 KEEP/KILL = 违规：要么补读正文，要么把该篇标为"仅摘要级、未判定"。
  - 与最接近的 2–3 篇工作，必须读到**正文的方法 + 实验**，并在 IDEA_REPORT 里引用具体章节/图表位置作为差异证据。
- 按**相同问题、相同方法、相邻领域**做三轮定向核查；逐篇对照最接近工作的正文方法、实验、图表和相关附录，记录覆盖范围、重合及差异。三轮不等于穷尽，核查范围写清楚。
- **查新范围必须覆盖非论文渠道**：HuggingFace discussion / GitHub issue / 博客 / 知乎 / arXiv 评论区也算"已公开"。这些渠道里的讨论、census、复现脚本，同样构成"已有先例"——只在 arXiv 搜而漏掉这些，会误判"空白"。
- **"找到空白"先问两句，再判断值不值得补**：
  1. 这个空白是否已在非论文渠道被公开讨论过？（若已被 HF/GitHub/博客做过更全的 census，则不新）
  2. 补上它，是否只是在给一篇弱引用的 preprint 打补丁？（若空白建立在源文隐性缺陷上，补它撑不起主会，则放弃）
- **撞车不是终点，是深挖的起点**：现象/方法已被做过 ≠ 全灭。撞车后先问一句——
  **这个已知现象里，有没有文献没测过的旋钮维度，能翻出一个文献没有的「可证伪新预言」？**
  （实战：捷径接管的一阶相变撞车 grokking 相变文献，但继续 k×r / k×d 扫描，翻出"宽度管捷径、深度管核心"的新预言，翻身达 ICML 门槛。）
- 查到相关工作后按**重合程度分级处理**，不一刀切淘汰：
  - **实质重复**（问题/方法/结论高度重合，**且深挖后翻不出任何可证伪新预言**）→ 淘汰，记入漏斗。
  - **部分重合**（覆盖其中一两项）→ 不淘汰；明确写出"我们和它的差异是什么、这个差异能否构成贡献"，
    差异站得住就继续，站不住才降级。
  - **相邻工作** → 作为背景与对比写入报告，不进入淘汰判断。
- 通过三轮核查后，产出一页纸 `IDEA_REPORT`：研究问题｜方法草图｜与最近工作差异（**逐条列、逐条论证差异是否成立**）｜待验假设｜证据路径｜实验计划，**交用户确认后才进入实验**。
- 与最接近工作比较时说明：任务划分、信息可见性、模型角色、预算、评分与基线。

## 3. 读论文与争议地图

### 3.1 拆论文（每篇只输出表格 + 要点）

逐篇读正文、实验、附录中与问题相关的部分，看图及图注：

1. 文献信息与摘要：标题、作者、版本、日期、链接、问题和方法。
2. 数据与方法：数据集、划分、基线、模型、预算、评分、实现。
3. 主要结果与证据链：结论、对应实验、数据、条件；区分作者观点与结果。
4. 每图支撑什么：图号、横纵轴、对照、作者用来支持的结论；看不清/无法核验就标记。
5. 局限性：作者声明的与未明说的弱点分开列，后者标注"分析/推断"。

未覆盖的章节、图表、附录明确列出，不以耗时承诺代替质量。

### 3.2 争议地图（按具体结论和实验条件组织，不按主题归类）

- **共识区**：多项独立研究支持的结论及适用范围。
- **分歧区**：冲突结果与各自证据，可能解释（数据/评测/模型/预算）标清谁是假设。
- **候选空白**：论文指出的 limitation 与 future work、尚待解决的问题、检索范围；不得仅因自己没找到就断言无人研究。

逐篇列出 Limitation / Future Directions 的要点与必要原文摘录；原文没单列就注明，不编造。回答：谁的证据更有说服力？空白值不值得做？现有数据/算力/方法能否切入？

### 3.3 领域知识沉淀（长期方向可选）

方向稳定后，把文献整理从"每次运行时硬想"升级为离线沉淀：轻量知识图谱（论文/模式/问题/领域节点），检索走多路召回（idea/domain/paper）+ 两阶段排序（先粗后精）；运行时用检索代替重新通读。

## 4. 实验循环

### 4.1 实验纪律（任何实验都遵守）

- **固定预算**：每次实验固定时间或算力墙钟，预算内一切改动（架构/超参/数据/规模）直接可比。
- **基线先行**：第一个实验永远跑未改动的基线。
- **评测只读**：评测代码、数据划分、指标定义对实验者不可改；指标唯一且事先声明。
- **结果日志**：每次实验记录 commit/配置、指标、资源占用、状态（keep/discard/crash）+ 一句话假设；日志重定向到文件，只 grep 关键指标，不让输出刷屏。**用 `scripts/experiment_log.py` 记与汇总**：`python3 scripts/experiment_log.py add --commit <hash> --metric val_bpb=0.99 --status keep --note "基线"`，然后 `list` 看 keep/discard/crash 统计。
- **推进机制**：有改进→保留（advance，随时可回退的"当前最优"）；无改进→回滚到基线状态；超时（约 2 倍预算）即杀，记 crash。小错（typo/缺 import）修后重跑；想法本身不通就记 crash 跳过。
- **简洁性准则**：同等情况更简单者优先；删代码性能不降是胜利；微小提升加大量丑复杂度不值。
- **无网对比**时遵守用户要求；不把既有试跑或部分结果说成正式复现、显著提升或因果证据。

### 4.1.1 自动跑小实验（何时可以、何时必须停）

实验循环**可以自动执行**，但要分清"门内"和"门前"：

- **门内（自动）**：满足以下全部条件时，主 agent 可直接派子 agent 跑小实验，无需再问用户——
  ① §2 查新已通过；② 用户已确认 IDEA_REPORT 与最小实验设计；③ 实验属于**小规模验证**
  （预算受限、秒级到分钟级、不动大规模算力）。子 agent 按 §4.1 纪律执行，见 §0 汇报要求回传
  配置/指标/状态/结论；主 agent 汇总后归纳规律。
- **门前（必须停）**：以下任一情况，**停下交用户审核，不得自动开跑或扩大**——
  ① 查新未通过或用户未确认；② 要把小规模结论升级为大规模训练/长实验；③ 要改评测代码/指标/数据划分；
  ④ 涉及新增外部依赖或不可回退的环境改动。
- 自动跑小实验时同样遵守 §0 的子 agent 三档规则：独立配置的实验用 A 档并行；
  下一批实验依赖上一批规律时用 B 档由主 agent 转述；评审/审计环节永远不得与实验执行者共享记忆。

### 4.2 海量小实验模式（预算受限/方向未定）

窄题切入 + 海量微型实验 + 持续归纳：

1. **窄题切入**：不碰大题目，先选具体、可快速回答的小问题当起点。
2. **微型实验替代长训练**：几百个秒级小实验模拟大规模训练，逐项改变深度/宽度/词表等因素。
3. **追问普遍规律**：每批实验后问"有没有一条简单规律在所有条件下都成立"，剔除不稳定结论。
4. **方向确定后自主搜索**：给足上下文让 agent 自己搜索-实验-验证，直到找到普遍成立的规律。
5. **公式化**：把规律写成可复用、可预测的公式。

约束：小规模验证的规律必须标注验证规模，"已验证（小规模）"与"待大规模实测"分开陈述；方向确立前后都做定向查新，通过三轮核查再投入；草稿阶段如实说明，不把小规模结果包装成最终结论。

### 4.2.1 造现象发现循环（现象驱动的默认入口）

这是"想出 idea"的第一来源，不是兜底方案（见 §1）。
**不假设空位存在、不凭空想 idea**，而是在一个能精确测量、能跑几百次的小系统里主动找异常/规律，找到再解释成 idea。
当 §2 挖空位反复 0 存活、失败模式从"被做过"迁移到"前提是错的"时，更应默认走这条路。
这是"海量小实验"的严谨版本，四件套缺一不可：

1. **预注册**：先写死系统规格、旋钮、读数、阈值、退出条件，**再看数据**。不许先看数据再改判标准（防事后解释 / p-hacking）。
2. **异常判定四关**（全过才算候选，不是"看到一个现象就宣告规律"）：
   ① 效应量够大（量化阈值写死在注册里）；② 在旋钮上变化够锐利（跳变或明确非单调）；
   ③ 跨种子可复现（独立种子重跑同向）；④ 不被已知规律解释（用教科书/已知规律做基线，残差够大才保留）。
    **但④不是淘汰线**：现象被已知规律"部分解释"不等于全灭——只要能再给出 1 个**文献没测过的可证伪新预言**
    （新旋钮维度 / 新交互 / 新相变刻画），就值得继续深挖，而不是因"撞车"直接弃线。
   另加多重比较校正（如 BH），并预留 holdout 旋钮区只用于复现，不在同一数据上反复挖。
3. **管道先验证，再解释数据**（对应 §4.1 基线先行的强化）：
   ① 同 seed 同配置逐位可复现；② 零步对照 = 随机水平（查评测有没有 bug）；
   ③ 任务标签可由独立实现重算一致；④ 已知规律的阳性对照方向正确。
   **任一不过 → 修管道，不许解释数据。**
4. **退出条件**：连续 3 轮无任何过四关的异常 → 换一组旋钮（不是调阈值）；约 8 轮全无 →
   承认此算力下造不出可发表现象，如实记录，回到"用户给问题"或换研究类型。

4.2.1 与 4.2 的关系：**4.2.1 造现象是产生 idea/窄题的入口**（先找规律，规律引出题目）；**4.2 是窄题已定后**的海量小实验（验证与细化规律）。顺序是 4.2.1 → 4.2 → §2 查新 → 上卡。
两者共享同一条铁律——**小算力只能证明小系统里的小规律，跨规模推广必须另行标注"待大规模实测"**。

### 4.3 自主性规则

进入实验循环后不询问"要不要继续/是不是停点"——人可能不在，循环持续到被手动打断。没想法时：回去读论文、组合之前的近失（near-miss）、尝试更激进的改动。但门前必须停：扩大实验规模前提交完整实验设计给用户审核。

## 5. 结果→结论

- **result-to-claim 审计**：每个结论过三问——结果真的支持这个说法吗（样本量、方差、基线、评测是否诚实）？结论是否超出实验条件范围？别人按日志能复现吗？
- **claim 状态机**：每个主张标 supported / invalidated / pending，写入 claim 清单；被推翻的及时降级。
- **汇报聚焦**：问题｜实际方法｜与最近工作区别｜已验证证据（含验证规模）｜下一步。用户要求简短时控制篇幅；建议没实施前不说成已实施。

## 6. 写作

- **先 story 后 paper**：先固化中间表示（标题/摘要/问题/方法/贡献/实验计划），确认叙事成立再展开成文；先跑实验后补叙事容易编故事。
- **写作契约**：图表与数据一致、引用真实且语境恰当、数字如实转录；生成的视图（HTML/幻灯片）可再生成，源文件（MD/TeX）才是单一事实源。
- **生成-评估-适配循环**：写→评→改，迭代中保持章节结构、论证一致性、图表对齐；评审意见分"计分"与"改稿建议"两层——计分严格可复现，改稿给字段级可执行建议。

## 7. 评审与审计

### 7.1 模拟挑剔审稿人（无跨模型条件时）

针对目标会议/期刊与具体方案输出：3 条 major concerns（各说明问题、证据、什么情形会推翻方案）；5 维可行性评分 1–5（创新性/数据可得性/技术难度/周期/预期贡献，说明理由与不确定性）；补强清单按"三个月内可做｜需更多资源｜暂不可判断"分档。分低可补的先补，无法补的考虑放弃。评分是研究判断，不代表录用概率。

### 7.2 锚定评审（有真实评审数据/先例库时）

不让模型直出分数（不可复现、难校准）。改成盲测相对判断：匿名化卡片（去掉标题/作者/分数等泄露信息，字段限长防"写长就赢"），只让评审对锚点做 better/tie/worse 判断，再对照锚点已知分数确定性反推得分；判断不一致时加密锚点重判。计分层与改稿层分开。

### 7.3 审计链（出终稿/投稿前，逐层过）

**用 `scripts/audit_chain.py` 驱动**：`python3 scripts/audit_chain.py` 逐层判定，或 `--report` 只看检查项；汇总层状态为 PASS/WARN/FAIL/BLOCKED。

先分清两类把关，别混：

- **编造检测**：客观可证伪，用工具/规则判，**不靠 LLM 猜**（LLM 判幻觉已被证实系统性误报）。
- **论证质量**：结论是否被支持、能否顶住反驳，可用 LLM 判（文本内部一致性，不需外部知识）。

#### A. 编造检测（五类，逐类给判据）

| 类型 | 判据 | 工具/动作 |
|---|---|---|
| 引用编造（号错/不存在） | 每个 arXiv/DOI 在官方源查得到且标题一致 | `scripts/verify_citations.py` → 输出 HR（错引数/总引数）；HR>0 即 FAIL |
| 归因编造（论文真、话假） | 引用的"声称内容"与原文一致 | 脚本返回真实标题 vs 报告声称，浅层对齐；正文级精读标"待核" |
| 数字编造 | 每个关键数字有来源锚点 | 抽含数字的断言 → 必须指向论文某表/某图或自己日志某行；指不出的降级为假设 |
| 结果编造（声称跑了没跑） | 每个实验结果能指回产物 | 强制 back-pointer：run.log / results.tsv / commit；缺 artifact 不算已证 |
| 状态编造（声称已核实） | "已核实/已验证/显著"有对应记录 | 状态词与日志/核验记录一一对应 |

#### B. 结论-证据一致性（对齐 intra-paper verification，arXiv:2607.26066）

用四个评审类别（源自 182 篇 ICLR 投稿 + 786 条真人评审归纳）组织：

- **Novelty**（新颖性声明是否成立）、**Methodology**（方法是否支撑声明）、**Clarity**（表述是否清楚）、**Other**。
- 流程：从报告抽 novelty claim → 检索方法/证据段落 → 判 **SUPPORTED / UNSUPPORTED** + 一句话理由。UNSUPPORTED 的 claim 必须降级为"假设"或删。

#### C. 最强反驳

写一封最强拒绝信，逐条评估能否顶住；顶不住的补强或降级主张。

任何一层不过就不出终稿；状态用 PASS/WARN/FAIL/BLOCKED 标注，WARN 以上必须处理或经用户知情同意。编造检测（A）任一 FAIL 即阻断，不得以"整体还好"带过。

## 8. 回应与改投

- **Rebuttal**：逐条拆解审稿意见，区分"可补实验/可澄清/立场分歧"；最小必要补强优先；产出可直接粘贴的回复稿。
- **改投**：硬约束下移植（如不补实验、不动 bib、不推翻原结论），改动范围用白名单约束，不覆盖历史投稿。

## 9. 领域适配（示例）

工作流方向无关；领域特定约定以"适配层"附加。例如 Harness²/agent 研究：保留原生组件与既有经验，分别评估"当前任务适配"与"未见任务迁移"；先核实实际运行、产物、有效评分与运行器版本再报告结果。

**子领域是硬约束，不是偏好**：算力决定能选什么子领域。单卡要出 A 类，只能选"小规模本身就是该领域标准"的方向（理论 / 公开工件取证 / 可塑性-持续学习）；RL 后训练、对齐几何、电路发现这类"7B 起步"的赛道，1 张卡补不齐结构性劣势。选题前先问：**这个子领域的标准规模，我的算力够不够到及格线？** 不够就换子领域，不是硬撑。

## 10. 实战教训（血泪换来的，别再犯）

来自 icml 单卡选题实战，每条已落实到对应章节：

1. **数学自洽 ≠ 新颖**——自己推出漂亮公式，先查新：很可能已有发表先例（实例：η_c≈m/‖g‖ 撞 2607.01083、2510.08539）。→ §2
2. **评测管道先验证**——没做 0 步对照就上卡，两个评测 bug 白烧 40+ 次跑。→ §4.1 基线先行、§4.2.1 管道验证
3. **先想 idea 再查新 = 高概率白做**——正确顺序：宽扫描找空窗 → 再设计。→ §1 现象驱动优先
4. **小算力只能得到常识**——135M–360M 的现象审稿人不关心；算力决定方向，不是努力决定。→ §4.2.1 铁律
5. **"找到空白" ≠ "值得补"**——空白可能早被非论文渠道公开，或建立在弱论文的隐性缺陷上。→ §2 找到空白先问两句
6. **子领域是硬约束**——见 §9。单卡别碰"7B 起步"的赛道。
